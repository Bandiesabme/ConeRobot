# Raspberry Pi Wi-Fi Hotspot Setup Guide
## Node 2 (Router) → Node 1 (Client) over Wi-Fi

---

## Hardware & Network Overview

| Role | Device | OS | Network Backend |
|------|--------|----|-----------------|
| **Node 1** — Client | Raspberry Pi (any model) | Ubuntu 24.04 Server | Netplan / systemd-networkd |
| **Node 2** — Router/AP | Raspberry Pi 5 | Raspberry Pi OS (Bookworm) | NetworkManager |

**Topology:**
```
[Internet]
    │ Ethernet
[Node 2 - RPi5]  ← Wi-Fi AP (SSID: Bandi, 10.42.0.1)
    │ Wi-Fi
[Node 1 - RPi]   ← Client (10.42.0.10, hostname: conerobot)
```

## Problems Encountered & Solutions

### Problem 1 — Pi Imager Hashes the Wi-Fi Password

**What happened:**
Raspberry Pi Imager, when configured with a Wi-Fi password, silently SHA-256 hashes it in the generated `network-config` file on the `system-boot` partition:

```yaml
# What Pi Imager wrote (WRONG):
password: "b7fca26bba52beb9c11e17df0bfebf7d9929c6fe3bdc260cda7982db302aa7df"
```

Ubuntu's Netplan expects a **plain-text** passphrase for WPA-PSK. The hashed string causes a silent authentication failure — no error is logged, the client simply never connects.

**Solution:**
After flashing, **do not configure Wi-Fi in Pi Imager**. Manually edit `network-config` on the `system-boot` FAT32 partition (readable on Windows) with the plain-text password before first boot.

**Critical warning:**
If Node 1 has already booted once, cloud-init marks itself as done and will **never re-read** `network-config` again. In that case, you must either reflash or mount the root (ext4) partition and edit `/etc/netplan/50-cloud-init.yaml` directly (requires Linux).

---

### Problem 2 — WPA2 RSN Information Element Mismatch

**What happened:**
Even with the correct plain-text password on both sides, the WPA2 4-way handshake failed. The symptom on Node 2 was:

```
authorized:  no    ← stuck here, never becoming yes
authenticated: yes
associated:  yes
```

The root cause is a mismatch in the **RSN Information Element (RSN IE)** — a data structure exchanged during the WPA2 handshake that declares which cipher suites and security features both sides support.

- **Node 2's AP** was configured as strict WPA2-only, AES/CCMP-only, with PMF in an unset/default state.
- **Node 1's wpa_supplicant** (generated by Netplan with minimal config) offered a broader set: WPA+WPA2, CCMP+TKIP, with its own PMF expectations.
- During handshake Message 3/4, both sides compared their RSN IEs — they didn't match → Node 1 aborted the handshake and disconnected itself.

This explains why there was **no reason code** in `iw event -f`: the client was the one leaving, not the AP kicking it.

**Solution:**
Make the AP's cipher advertisement flexible enough to intersect with the client's offer:

```bash
# On Node 2:
sudo nmcli connection modify Hotspot \
  wifi-sec.pairwise "tkip ccmp" \
  wifi-sec.group   "tkip ccmp" \
  wifi-sec.proto   "wpa rsn"   \
  wifi-sec.pmf     disable

sudo nmcli connection up Hotspot
```

### Problem 3 — Floating DHCP IP (Node 1 changed IP on reconnect)

**What happened:**
Every time the hotspot restarted or Node 1 reconnected, dnsmasq assigned a different IP address (`10.42.0.178`, then `10.42.0.179`, etc.), making SSH access unreliable.

**Solution:**
Create a static DHCP reservation on Node 2 tied to Node 1's MAC address:

```bash
# On Node 2 (replace MAC with Node 1's actual wlan0 MAC):
echo "dhcp-host=88:a2:9e:ba:75:c5,conerobot,10.42.0.10" | \
  sudo tee /etc/NetworkManager/dnsmasq-shared.d/node1.conf

sudo nmcli connection up Hotspot
```

Node 1 will always receive `10.42.0.10`.

---

### Problem 4 — Wi-Fi Dropping Carrier Every 1–4 Minutes

**What happened:**
Node 1's Wi-Fi connection repeatedly dropped and reconnected throughout operation:

```
wlan0: Lost carrier
wlan0: DHCP lease lost
wlan0: Gained carrier        ← reconnects almost instantly
wlan0: DHCPv4 address 10.42.0.179/24 acquired
# ... repeats every 1-4 minutes
```

Root cause: Linux Wi-Fi defaults to **power save mode** (`Power save: on`). The radio periodically sleeps to conserve power. The AP interprets the silence as a disconnection and deauthenticates the client, causing the carrier drop/reconnect cycle.

During each drop, ICMP (ping) and SSH packets were lost, making Node 1 appear unreachable.

**Solution:**
Disable Wi-Fi power save permanently on Node 1:

```bash
# On Node 1 — install iw if needed:
sudo apt install iw -y

# Disable immediately:
sudo iw dev wlan0 set power_save off

# Make permanent via systemd service:
sudo tee /etc/systemd/system/wifi-powersave-off.service << 'EOF'
[Unit]
Description=Disable Wi-Fi Power Save
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/sbin/iw dev wlan0 set power_save off
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl enable --now wifi-powersave-off.service

# Verify:
iw dev wlan0 get power_save
# Expected: Power save: off
```

## Full Setup Guide (From Scratch)

Follow these steps in order to reproduce this setup cleanly.

---

### Phase 1 — Configure Node 2 as Wi-Fi Hotspot

> Run all commands on Node 2 (Raspberry Pi OS / Bookworm).

**1. Create the hotspot with relaxed cipher settings:**

```bash
# Create the hotspot
sudo nmcli device wifi hotspot ifname wlan0 ssid Bandi password 1234445678

# Immediately apply relaxed cipher settings (fixes RSN IE mismatch with Ubuntu clients)
sudo nmcli connection modify Hotspot \
  wifi-sec.pairwise "tkip ccmp" \
  wifi-sec.group   "tkip ccmp" \
  wifi-sec.proto   "wpa rsn"   \
  wifi-sec.pmf     disable

# Enable autoconnect on boot
sudo nmcli connection modify Hotspot connection.autoconnect yes

# Apply changes
sudo nmcli connection up Hotspot
```

**2. Verify the AP is running:**

```bash
nmcli connection show Hotspot | grep -E "ssid|psk|pairwise|group|proto|pmf|method|autoconnect"
sudo journalctl -u NetworkManager | grep "DHCP\|dnsmasq" | tail -5
```

Expected: DHCP range `10.42.0.10 -- 10.42.0.254` active.

**3. Create a static DHCP reservation for Node 1** *(do this after you know Node 1's MAC)*:

```bash
# Replace the MAC address with Node 1's actual wlan0 MAC
echo "dhcp-host=<NODE1_MAC>,conerobot,10.42.0.10" | \
  sudo tee /etc/NetworkManager/dnsmasq-shared.d/node1.conf

sudo nmcli connection up Hotspot
```

---

### Phase 2 — Flash and Configure Node 1 (Ubuntu 24.04 Server)

> Run on your Windows machine.

**1. Flash the SD card using Raspberry Pi Imager:**
- Select: **Ubuntu Server 24.04 (64-bit)**
- In **OS Customisation**:
  - Set hostname: `conerobot`
  - Set username: `conerobot` (or your choice)
  - Set password
  - Enable SSH
  - **❌ Do NOT configure Wi-Fi here** — Pi Imager hashes the password

**2. After flashing, open the `system-boot` partition** (appears as a drive in Windows Explorer — it's FAT32).

**3. Edit `network-config`** with Notepad or VS Code *(not Word)*:

```yaml
network:
  version: 2
  wifis:
    wlan0:
      dhcp4: true
      access-points:
        "Bandi":
          password: "1234445678"
      optional: true
```

> [!IMPORTANT]
> Save as **UTF-8** encoding with **LF** (Unix) line endings — not CRLF.
> Ensure the file is named `network-config` with **no `.txt` extension**.
> This only works on a **fresh flash** where cloud-init has never run.

**4. Safely eject the SD card and insert it into Node 1.**

---

### Phase 3 — Boot Node 1 and Verify Connection

**On Node 2, monitor for Node 1's DHCP lease:**

```bash
sudo journalctl -u NetworkManager -f | grep -iE "DHCP|10\.42"
```

Wait ~60–90 seconds. You should see:
```
DHCPDISCOVER(wlan0) <node1-mac>
DHCPACK(wlan0) 10.42.0.10 <node1-mac> conerobot
```

**Verify Node 1 is authorized (not just associated):**

```bash
watch -n 2 "iw dev wlan0 station dump | grep -E 'Station|authorized|connected'"
```

Expected:
```
Station 88:a2:9e:ba:75:c5 (on wlan0)
    authorized:  yes
```

---

### Phase 4 — SSH into Node 1 and Finalize

**SSH using hostname (via avahi mDNS) or IP:**

```bash
ssh conerobot@conerobot.local
# or
ssh conerobot@10.42.0.10
```

> [!NOTE]
> `conerobot.local` works because `avahi-daemon` was installed via `user-data` cloud-config.

**Disable Wi-Fi power save (critical for stability):**

```bash
sudo apt install iw -y

sudo tee /etc/systemd/system/wifi-powersave-off.service << 'EOF'
[Unit]
Description=Disable Wi-Fi Power Save
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/sbin/iw dev wlan0 set power_save off
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl enable --now wifi-powersave-off.service
iw dev wlan0 get power_save
# Should return: Power save: off
```

**Set up SSH key authentication** *(from your main machine)*:

```bash
ssh-copy-id conerobot@conerobot.local
```

## Verification Checklist

Run these on Node 1 after full setup to confirm everything is healthy:

```bash
# 1. Wi-Fi connected with correct IP
ip addr show wlan0 | grep "inet "
# Expected: 10.42.0.10/24

# 2. Gateway reachable
ping -c 3 10.42.0.1

# 3. Internet reachable
ping -c 3 8.8.8.8

# 4. Power save disabled
iw dev wlan0 get power_save
# Expected: Power save: off

# 5. No carrier drops in the last hour
sudo journalctl -u systemd-networkd --since "1 hour ago" | grep "Lost carrier"
# Expected: no output
```
